第一部分｜诊断首稿

01｜AI输出的问题

第一稿看着像样，用起来却平庸

AI不再答非所问，它交回的第一稿，信息都在、格式齐全，可就是没法直接用。

这层差距就体现在第一稿上：信息都在，格式齐全，读起来就是“还行”，一股模板味。

一份真实的第一稿

任务交代得明明白白，“帮我写一篇蜜雪冰城联名的推广文案”，AI 交回来的是一长篇文案：

蜜雪冰城联名 #雪王出道 #夏日限定 #好喝不贵”

三个AI痕迹

通读一遍，哪里不对劲，一眼就能看出来。

  1. 破折号堆砌：“限定联名饮品 ——”“限量联名周边 ——”“打卡赢福利 ——”，连着三个破折号，AI 文案的高频特征。
  2. 固定句式：“不仅……更有……”“和雪王一起解锁”，都是套路化模板。
  3. 没有具体信息：“XXX品牌”“X月X日”“X元起”，全是占位符，等于没说。

文案看着完整，关键的事实一个都不确定。这就是“平庸”的样子：规矩都守住了，却哪里都不出彩。

02｜问题根源

两个根源

平庸是你们俩一起造成的：AI默认只能给最安全、最常见的答案，而你还没给它“不好”的判断标准。

  1. AI 默认讨好你：它要的是你的“赞”。你没说想要什么，最可能被点赞的就是最安全、最常见的那一个：平淡、套路、不敢给尖锐的观点。
  2. 没给它“不好”的标准：它不知道什么是“好”，更不知道什么是“不能用”，只能凑合。

从诊断到修改

这些问题，下面逐个讲五个常用解决方法。

第二部分｜改到能用

03｜按问题挑方法

五个方法各补一个缺口

按问题选方法

首稿平庸，先别急着修。看清是哪个问题，再挑对应的方法。

方法 解决什么
生成多个方案 方向不对，这一份怎么修都修不好
加约束 方向对了，写法 AI 味重
做渐进迭代 长任务，等了好久，结果不符合预期
提中立问题 答案带了倾向
让它挑刺 表面没毛病，就是不够锐

五个里面，需要哪个用哪个，不用每次都凑齐。

生成多个方案

方向不对的时候

别在这一份身上继续修：让它出多份不同风格的方案，从中挑方向。

AI 默认给最常见、最不会错的那个答案。继续修这一份，等于让它把那个答案再打磨一遍，方向没变。多份方案加上指定不同风格，才能把它逼出安全区。

加约束

写法 AI 味重、又长又空的时候

约束是提前划给 AI 的线：不许说什么、多少字、什么形式。

AI 默认按最常见的写法给回答，写法容易撞出同一个 AI 味；也默认想“把能说的都说全”，又长又空。同一个模型对同一类任务，走的就是同一条默认路，默认输出撞出来的总是那种 AI 味。约束把这些默认项一条条改掉。

四类约束

  1. 禁用清单：把不许用的词一条条列出来：破折号、“不仅……更是……”、“总而言之”“值得注意的是”。
  2. 形式约束：定总字数和输出形式，列表还是表格，一次说清。
  3. 好坏参照：贴一个好例和一个坏例，指出希望它学哪里：说话的口气，还是每句话里装多少内容。
  4. 正向表述：把每一个“不要”改成“只做某事、做到什么程度”：“不要编数字”改成“只使用我提供的数字，没有的写‘待补’”，“不要太啰嗦”改成“每段最多三句”。

四类约束最后都写进提示词里：“禁止：破折号、‘总而言之’这类水话。格式：300字以内，用表格输出。”把“别太 AI 味”变成能一条条对照的规矩，AI 才有具体的修改依据。

参考：吴恩达《AI Prompting for Everyone》笔记、关于提示词工程的100个问题。

做渐进迭代

整篇模板文的时候

长任务一次要全文，AI 只能套最常见的结构。结构不在大纲阶段定下来，后面怎么修都修不好。

直接要全文，AI 只能给最常见的结构：背景、现状、挑战、展望，一套走下来。结构定在大纲阶段，是纠偏最便宜的时候；正文写出来之后，再多的修改也只在表面。

三轮，每轮只改一小点

  1. 第1轮｜出三份大纲：“请给3份不同侧重的大纲：A 供应链 / B 营销 / C 门店运营。”看大纲就知道每个方向的重心，挑一个。
  2. 第2轮｜选方向细化：“选 B 方向，细化到三级标题，并标注每部分需要什么数据、什么案例。”结构不对，现在改只要一句话。
  3. 第3轮｜逐章展开：“按细化后的大纲写第2章完整内容，每个论点要有真实案例。”

纠偏放在结构层面，效果大于对着正文死磕。

提中立问题

要客观分析的时候

要客观分析，就用中性表达，别暗示结论。

大模型愿意顺着你的倾向说，它把顺着你说当成最稳的回答方式。

问“大厂的活儿干够了，跳槽去创业公司值不值？”，它只回一面：“创业公司成长快，能学到的东西多，值得去。”把问法换成“请列出从大厂跳槽到创业公司的利弊，覆盖薪资、加班强度、成长空间，不要偏向任何一方。”，利弊才摆得匀，决定权在你。

暗示藏在问法里：“X 是不是更好？”这种是非问句，问句里已经带了方向，改成“研究对 X 和 Y 的对比有何看法？”才中立。所以养成一个习惯：检查问句里有没有藏着答案。

参考：吴恩达《AI Prompting for Everyone》笔记。

让它挑刺

表面没毛病，但不够锐的时候

别告诉它“改好点”，让它站在读的人立场挑刺，追问就是修改清单。

你说“再改好一点”，它给你同样的稿子磨光一点。挑刺走的是另一条路：让它站到读的人的位置上，把尖锐的问题问出来，缺口被问出来，比被改出来清楚。

做法，直接把这句话发给它：“假设你是我的老板，看完上面这份门店经营周报，1. 提出三个最尖锐的追问，专挑数据缺口和逻辑跳跃。2. 告诉我你希望下一版里看到哪些内容。只提问和点题，不要替我回答。”

问回来的会是“利润涨了三成，只看了线上渠道，线下门店的数据呢？”“对标的是上季度的同行，这个月隔壁刚换了打法”这类。把追问贴回去让它照着重写，第二轮就有准头了。

04｜开新对话

越聊越笨

原因很简单：窗口被你的对话填满了。

会话，就是你正在用的这个对话窗口。每聊一轮，都往窗口里堆一层：早期的消息被新消息挤到对话的“中间带”，注意力最弱的位置。它们还在，只是被埋了。你添的每一句闲谈，都会变成干扰项。

一个案例

一位设计师抱怨 AI 绘画越用越差，对着提示词折腾了几个星期，回头一看：过去一个月，他把三十多张不同项目的参考图全丢进了同一个会话。

AI 拿着三十张风格各异的图找共性，产出越来越像缝合怪。最后开一个新窗口，画就好了。

实测数字

两组独立研究，测出了同一件事。

  1. 斯坦福长上下文实测：信息放在开头或结尾时准确率最高，埋在中段时下降超过三成。连专门标榜长上下文的模型也一样。
  2. 18个主流模型实测：有的模型输入到五六百词就开始衰减；上下文里塞进一个无关干扰项，质量就有可测的下降，塞到四个，质量成倍跌。

Anthropic 官方把这两组结论编成一句原则：上下文是一种有限的资源，塞得越多，新塞的每一条就越不值钱。

一百万 token 的窗口装得下海量内容，真正重要的是把窗口留给和当前任务相关的信息，越干净越好用。

先分清哪种笨

同样越聊越笨，原因可能是两类，处理办法完全不同。

  1. 抖动型：同样问题每次答案略不同 → 那是模型自己的随机性，用固定格式锁住，不用开新窗。
  2. 窗口问题：开始引用你早就废弃的旧方案，前面立的规矩也不听了。那是上下文里垃圾太多，开新窗。

信号有三个，任出现一个就开新窗。

  • 任务主题变了：从写方案切到查数据，旧上下文全是负担。
  • 素材来源换了：上一个客户的资料还在窗口里，下一个客户的判断会被污染。
  • 聊得太久了：会话拉了很多轮，质量明显下滑，早期的规矩已经被埋了。

让窗口保持干净

规矩别被埋

规矩会失位，要把它带回“现在”。

你在第3条消息立的规矩，到第30条消息时，正躺在注意力最弱的位置上。把它带回来有两招，按优先级排：

  1. 写进常驻位：重要约束放进“自定义指令”“风格偏好”或系统提示这类位置。常驻位不受会话长度影响，规矩全程有效，不用每轮重复。
  2. 中途捞回来：长会话中途，用一句话把规矩捞回来：“继续遵守：不许编数字、输出保持表格。”让它开工前先复述一遍关键约束，更稳。复述过的规则，比听过一次的规则硬。

迁移包

开新窗口，只带结论，不带过程。

关旧窗前花三十秒把结论打包，新窗的起点就比“从零开始”高一大截。

本任务目标：【一句话】
已确认的决定：【列点】
必须遵守的规矩：【从旧会话抄过来】
请基于以上继续：【当前要做的事】

旧会话里那些被否掉的方案、走弯的路，都是新窗口的干扰项，留在旧窗口里陪葬。

两个日常习惯

窗口里的历史越积越多，注意力越薄。该留的是结论，整段对话不用留。

  • 按项目开窗：同一个项目的讨论共享一个窗口，跨项目绝不混。
  • 按天清理：收工时把结论写进笔记，第二天开新窗带结论开工。

长文档交给 AI，先让它提取相关段落再分析，整份贴进去，大部分字和这次任务无关，都成了干扰项。

第三部分｜组合与速查

05｜每轮推进一步

首稿拿来当底子，方法放进逐轮修改的过程里，一轮干一件事，改动看得见。

首稿的问题常常是叠着的：方向偏一点、AI 味重一点、水话多一点、结构平一点。想一次修完，就得把方法全堆进一句提示词，约束互相踩，和没装刹车一样。把方法放进逐轮的过程里，每轮只干一件事，改动看得见：

  1. 第1轮｜定方向（提中立问题、生成多个方案）：“不要偏向任何一方。先给几份不同侧重的大纲。”→ 看大纲，挑方向。
  2. 第2轮｜定结构（做渐进迭代）：“按挑中的方向细化到三级标题。”→ 结构定下来了。
  3. 第3轮｜压AI味（加约束）：“按大纲逐章展开。禁止：破折号、‘不仅……更是……’、‘让我们一起’。”→ AI 味被压住，正文落地。

上面三轮是长文分析类任务的常见节奏。问题多的时候，哪个问题要紧就先做哪个，后面的轮次接着清；改到位了就停，不用跑满三轮。

06｜按场景查句式

要写东西的时候

九个场景，第一种用法：做东西。按场景查句式，换上自己的内容就能开工。

写文案 / 起草内容

你是[角色]。请为[对象]写[内容类型]。
要求：[格式 / 字数 / 语气]
禁止使用：[AI 特征列表]
参考风格：好例「……」、坏例「……」

做创意 / 头脑风暴

请为[主题]提供[数量]个[创意类型]，风格分别覆盖：
A)[风格1] B)[风格2] C)[风格3]
每个创意必须包含[具体元素]。

写长文 / 报告

分步执行，不要一次写完：
① 拟定[数量]份不同侧重的大纲
② 选方向，细化到三级标题
③ 按大纲逐章扩展，案例支撑

改写 / 翻译 / 润色

请将以下内容改写为[目标风格]。
保持原意不变，只调整[语气 / 措辞 / 篇幅]。
参考样本：[一段目标风格的示例文本]

提取信息 / 整理数据

请从以下内容中提取[字段A]、[字段B]、[字段C]。
用[表格 / 分点列表]输出。
找不到的标注[未找到]，不要编造。

要判断东西的时候

九个场景，第二种用法：判断。先做后判，判断类的句式都带着中立要求。

做分析 / 做对比

请客观分析[主题]，从[维度A]、[维度B]、[维度C]三个角度展开。
不要偏向任何一方。
用[表格 / 分点]输出。

做调研 / 做研究

请研究[主题]，时间范围[起止]。
仅使用[权威来源类型]的数据和报告。
请非常深入地分析。

做决策 / 选方案

我面临[决策场景]。请列出[数量]个可选方案。
每个方案给出：最佳情况、最差情况、最可能结果。
先让“乐观派”和“怀疑派”各陈述最强三点，再互相反驳一轮，最后综合给推荐。
被反驳掉的观点不要复活。不要偏向任何方案，由我做最终决定。

审查 / 评估 / 打分

请从[维度A]、[维度B]、[维度C]评估以下内容。
每个维度先给出评分(0-10)和具体理由，最后再汇总总分。
评分标准：[每个维度的具体标准]

小结

  1. 首稿平庸有原因：AI 默认给“最安全、最常见”的答案，你还没给它“不好”的标准。看清原因，修改才有方向。
  2. 按问题挑方法，逐轮改：方向不对就让它出多份不同风格的方案；AI 味重、又长又空就加约束；模板文就先出大纲再展开；要客观就用中性表达；不够锐就让它挑刺。
  3. 让窗口保持干净：聊得越久，注意力越弱。任务变了、素材换了、聊得太久了，就开新窗，把结论带走就行。

首稿只是起点。问题看得越透，逐层细化得越到位，结果才越接近“能用”。
