第一部分｜用 MD 组织与保存文字

01｜MD 的价值

Markdown：AI 世界的普通话

  • AI 读写最顺手的格式：AI 本来就处理文字，MD 是它读写最顺手的格式，AI 和文件之间来往的内容基本都是 .md。
  • 处理更快，token 更省：MD 的结构用符号标出，没有 PDF、PPT 的排版噪音，同样的内容交给 AI，处理的 token 更少，速度更快。

参考：普通人最该补的4门AI工具：MD、HTML、GitHub、Skill。

02｜MD 的结构

MD 是一种干净规整的文字格式，用简单符号标出内容结构，AI 读起来比 PDF、PPT 省力。

符号长什么样

  • # 是标题：行首加 # 表示一段的标题，# 越多级别越低。
  • - 是列表：行首加短横线的条目变成列表。
  • | 是表格：竖线把文字对齐成表格。
  • 一对星号包住的文字加粗：正文里最常用的强调方式。

为什么 AI 读起来省力

同样一份内容，放在 PDF 或 PPT 里，混着页码、分栏和装饰性排版，AI 要先分辨哪里是排版、哪里是正文；MD 直接用符号标出结构，正文里没有排版干扰，AI 可以直接读、直接重排、继续加工。

同一份文字，结构越清楚，AI越容易找到该读的内容。

参考：普通人最该补的4门AI工具：MD、HTML、GitHub、Skill。

03｜使用 MD 工具

MarkText 负责打开 .md，Docling 负责把零散资料转成 MD。

  1. MarkText：免费开源的 Markdown 阅读器，像打开普通文档一样打开 .md 文件。
  2. Docling Skill：免费开源，把 PDF、Word、PPT、Excel、HTML、图片和扫描文档转成 Markdown，转完直接交给 AI 处理。

参考：MarkText、Docling、普通人最该补的4门AI工具：MD、HTML、GitHub、Skill。

第二部分｜用 Skill 复用成熟的工作方法

04｜Skill 的价值

Skill：越用越值的技能

问题

把同类任务交给 AI，每次都要从头交代：看什么、按什么格式输出、检查什么。

写进 Skill 之后

把这套做法写进一个 Skill，以后同类任务只要说做什么，AI 就按写进 Skill 的做法执行。例如把周报的写作要求写进一个 Skill，以后每份周报都按同一套标准生成。

参考：普通人最该补的4门AI工具：MD、HTML、GitHub、Skill。

05｜Skill 的结构

Skill 的标准架构

Skill 是把「一类任务怎么做」打包成的文件夹，里面只有 SKILL.md 是必须的。

Skill像一个工具箱：说明书必备，脚本、参考资料和样板按需配齐。 - SKILL.md（必须）：一份说明文件，开头是元数据（name、description，给 AI 判断要不要用），后面是正文，写清先做什么、最后交付什么、怎样检查。 - scripts/（可选）：可执行代码目录，把固定步骤写成能直接运行的脚本。 - references/（可选）：参考文档目录，做这类活要查的背景、规范、清单。 - assets/（可选）：资源文件目录，现成的样板文件，套着用。

SKILL.md 长什么样

SKILL.md 扫一眼就知道它写什么。

SKILL.md的开头帮助AI判断是否适用，正文再说明具体怎样做。 SKILL.md 分两段：开头元数据写 name 和 description，让 AI 知道这个 Skill 是干什么的、什么时候该用；后面正文写目标、步骤和示例，AI 照着执行。

06｜按需加载

装了很多 Skill，也不影响使用。

三层按需加载

  1. 启动时，只读名称和描述：每个装上的 Skill 只占一行简短说明。
  2. 判断相关时，加载完整说明：当前任务对上某个 Skill，才读它的 SKILL.md 完整内容。
  3. 执行需要时，才查具体材料：里面的参考资料和脚本，做到那一步才读。

所以 Skill 可以装得多：给 AI 很多固定做法，又不把所有内容一直堆在它的短期记忆里。

07｜使用热门的 Skill

先用成熟的 Skill，摸清它解决什么问题。

  1. 找：明确需求，让 AI 去 GitHub 帮你找。 - 提示词：去 GitHub 寻找 Skill，Skill 用于【你的使用场景】。优先寻找高 Star、近两个月有维护提交的热门活跃项目。找 3–5 个，每个给出一句话特点让我快速了解。
  2. 用：指明某个 Skill，让 AI 帮你安装。实际使用过程中，AI 根据任务自动匹配调用，你也可以指定用哪个 Skill。
  3. 改：根据自己的习惯、表达方式和交付标准调整，多用几次，把修改意图告诉 AI，让它跟你讨论并调整 Skill。

参考：普通人最该补的4门AI工具：MD、HTML、GitHub、Skill、模块五_课2_WorkBuddy入门（Skill 节）。

08｜制作自己的 Skill

把自己的重复工作沉淀成 Skill。

四步

  1. 选一件经常重复做的工作。
  2. 与 AI 完整完成一次，把流程跑通，确认效果。
  3. 把流程整理成五类信息：什么时候用、提供什么资料、按什么步骤执行、最后交付什么格式、用什么标准检查。
  4. 封装为 SKILL.md，边用边测，持续调整。

适合的工作（示例）

  • 日常执行与协作：会议纪要、周报整理、方案检查、资料汇总。
  • 分析与决策支持：经营分析、项目复盘、招聘评估、决策简报。

参考：普通人最该补的4门AI工具：MD、HTML、GitHub、Skill。

第三部分｜用 GitHub 查找与获取资源

09｜GitHub 的价值

GitHub：全网最慷慨的地方

能找到什么

许多 AI 工具、提示词、Skill、Agent 项目、教程和资源合集，都会发布在 GitHub 上。

可以理解成三个东西的结合体

  1. 程序员的作品集：项目就是别人的作品，公开可看、可复制。
  2. 开源项目的资料库：工具、资料、技能包都公开在这里。
  3. 技术世界的趋势榜单：Star 排行就是热度排行，能看出技术世界正在做什么。

参考：GitHub、普通人最该补的4门AI工具：MD、HTML、GitHub、Skill。

10｜逛 GitHub

要资源的时候，把需求丢给 AI 直接搜。

  1. 进 GitHub 搜：打开 GitHub，在搜索栏输入关键词，检查结果。
  2. 让 AI 搜：在 AI 对话框里把需求说清楚，让 AI 帮你搜，结果直接给你。

参考：普通人最该补的4门AI工具：MD、HTML、GitHub、Skill。

11｜看懂项目

Star、提交记录、About，三处看完，就知道仓库值不值得用。

  • Star 星标：相当于收藏数，越高说明仓库越热门。
  • Commits 提交记录：近期有提交，说明项目还在活跃维护。
  • About 仓库说明：读一遍，快速弄清这个仓库做什么、适不适合你的需求。

三处一起看：Star 高只说明热门，还要看需求对不对得上。

参考：普通人最该补的4门AI工具：MD、HTML、GitHub、Skill。

12｜使用项目

下载下来丢给 AI，AI 就是你的翻译官。

  1. 进仓库页面，点右上角绿色的 Code 按钮，选 Download ZIP，把项目下载下来。
  2. 把下载的文件丢给 AI：“读懂这个项目，教我怎么用。”

参考：普通人最该补的4门AI工具：MD、HTML、GitHub、Skill。

第四部分｜用 HTML 把文字做成页面

13｜HTML 的价值

HTML：文字变作品的魔法

一段文字缺什么

AI 的回答通常是一段文字，关掉对话就是一段记录，能看，不好展示、不好使用、不好发给别人。

变成作品之后

  1. 能展示：产品落地页（产品介绍页）、数据看板、互动小工具、个人作品集。
  2. 能分享：发给同事或客户，对方打开看到同一个页面。

参考：普通人最该补的4门AI工具：MD、HTML、GitHub、Skill。

14｜HTML 的真相

HTML 是浏览器直接打开的网页文件，AI 会写，不用自己学。

描述页面的文字文件

文字放哪、图片放哪、按钮表格放哪、点了怎么反应、怎么计算、页面怎么动态变化，都写在这个文件里。浏览器读这份描述，把它变成看得见的页面。

打开就能用

不用额外装软件，电脑里现成的浏览器就能打开 HTML 文件。也不用自己学写 HTML，AI 写出来存成文件，浏览器打开就能用。

同一份描述，经过浏览器呈现，就变成能看、能点的页面。

参考：普通人最该补的4门AI工具：MD、HTML、GitHub、Skill。

15｜Skill 推荐

从零到好看，每一步都有现成的 Skill 可用。

三个 Skill，三种选择

  1. UI UX Pro Max｜重量级，从零搭建：一套厚重的网页设计工具箱，配色、字体、布局、图表和交互规则都准备好了，适合从零制作完整网页。
  2. Impeccable｜用来精修：网页精修 Skill，改善排版、配色、动效和使用体验，适合把「能用」提升到「好用、好看」。
  3. Design Taste Frontend｜轻量级，审美纠偏：轻量化的网页审美纠偏 Skill，减少 AI 生成网页常见的模板感和廉价感，适合落地页、作品集或快速改造现有网页。

参考：UI UX Pro Max、Impeccable、Design Taste Frontend、普通人最该补的4门AI工具：MD、HTML、GitHub、Skill。

小结

  1. MD 管组织与保存：AI 世界的普通话，文字存得规整，AI 加工更省更快。
  2. Skill 管复用：越用越值的技能，同类任务不再从头教。
  3. GitHub 管资源：工具、资料、技能包都能找到，全免费。
  4. HTML 管展示：AI 的输出变成能打开、能分享、能用的页面。

组织靠 MD、复用靠 Skill、找资源靠 GitHub、展示靠 HTML，AI 写作就成了一套。
